# Current architecture enforcement

Authority is spec/architecture/README.md -> baseline.md -> canonical Frozen Architecture SRC-01..07 and approved ADRs. This tool guide is subordinate.

Use `python3 ci/check_architecture.py --scope governance`, `--scope go`, `--scope java`, or `--scope all`; `--json` includes actual violations and parsed graphs. Any violation or unavailable Go parser exits nonzero. Root whitelist is explicit; every discovered Go file is parsed using standard go/parser including inactive build tags. Imports are actual AST imports for the present single module, not inferred from filenames. Go route/SQL strings and persistence calls reject business moved into root/shared or forbidden writers; declarations are recorded for Review, arbitrary assembly-helper names are permitted. Java current source declarations, imports, wildcard/static/qualified/same-package references, Unicode escapes and typed JDBC persistence calls are inspected. Shared connection creation and Gateway readonly Session queries remain supported. Java first service implementation expires the named InfraPlaceholder exception. Current Java transport compiles in the Java job; isolated legal future Java fixtures compile under an explicitly provisioned JDK in architecture job. Source, placeholder and fixture checks are never permanently skipped because Java business has not begun.

Run `python3 -m unittest discover -s tests/architecture -v` and `python3 -m unittest discover -s tests/ci -v`. Disposable fixtures exercise real Go parsing, compiled legal Go and future Java structures, root business disguised in main/tests, moved shared business, reversed imports, cross-service alias/build-tag/qualified/Unicode dependencies, current/expired Java placeholder, conflicting active task paths, workflow suppression/omission, governance triggers, deletion/rename and required job missing/skip/failure/cancellation.

Static checking cannot establish every possible business meaning or replace semantic independent Review. Review inspects real responsibility and runtime graph, including Core Auth write ownership and Gateway only required read validation/connection abilities. Routes/SQL/function patterns are evidence-based guardrails for canonical/current responsibilities, not an alternate contract or automatic complete correctness proof. Current package/module changes require adapting the graph tests; no three-module/binary mandate or new product dependency is introduced.

CI preserves profile-local changes and shared public-contract full compatibility selection. Governing Markdown, Agent entry, handoff, current task/template/batch/acceptance/governance, checker/tool/test changes select architecture plus actual Go/Java source checks. Diff enumeration uses --no-renames and includes deleted paths. Architecture validates canonical integrity/structure, current task references/scopes and checker controls. Separate source_go/source_java report actual trees; gate consumes all three required outcomes with no continue-on-error or waiver.

During bounded stage003, original Go layout failure is expected and remains a real source_go failure and overall hosted Gate failure. Independent acceptance of checker effectiveness uses successful exact-head architecture/classification/Java checks plus the specific independently verified old-Go failure inventory; it is not hosted-run PASS, Go compliance, batch PASS or S1 Gate PASS. This temporary deliverable scope authorizes only stage004 migration next and expires on its acceptance. ## Active client technology guard

`python3 ci/check_architecture.py --scope clients --json` is required in architecture; `--scope all` includes it. It resolves the canonical hash-bound policy and ADR-0005, then checks active shared/Web/Desktop/Mobile sources, configuration, explicit package/Cargo dependencies, JS/TS imports, client build commands and all current workflows. TypeScript business source, normal configuration/resources and limited Desktop Rust native files are supported. Mobile runtime/framework remains unapproved; Desktop uses Tauri + SQLx(SQLite) atomic adapter, no independent plugin execute-call transaction. Package aliases in Cargo are checked by actual package name. Client source/config deletions select architecture and applicable client jobs; root package/build configuration selects all jobs. Historical ADR/evidence/Recorder paths are not active client source and remain untouched.

Unapproved dependency/source/runtime/framework declarations fail even with permissive task paths and successful unit tests. Task `client_*` declarations are checked against authority, never used as approval. Guards are bounded static evidence: semantic Review must reject invented free-form task choices, indirect/dynamic dependencies, business disguised in native Rust, or API/protocol/model/plugin SDK moved outside TypeScript. New accepted technology decisions require updating authority/policy and effective positive/negative checks before implementation; no task-only allowlist.
