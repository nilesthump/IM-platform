# Canonical PostgreSQL schema

`migrations/0001_initial.up.sql` is the shared schema for Go and Java profiles.
Run the migration before application startup, using a normal PostgreSQL `psql`
client and libpq connection settings (`PGHOST`, `PGPORT`, `PGUSER`, `PGDATABASE`,
and secure credential handling outside the command line):

```text
python3 contracts/database/migrate.py status
python3 contracts/database/migrate.py up
python3 contracts/database/migrate.py down --allow-data-loss
```

The runner applies each SQL file and its checksum ledger entry in one transaction
under a PostgreSQL advisory transaction lock. Applied SQL is immutable. The down
migration drops all product tables and requires explicit data-loss acknowledgement;
release rollback still requires a backup and compatibility assessment.

`sessions` is one row per `(user_id, client_type)` slot. A replacement login must
rotate `session_id`, increment `session_epoch`, and revoke the old session in one
transaction. The server must validate both session ID and epoch against PostgreSQL.
The database constraints reject duplicate normalized friendship and DIRECT pairs,
request IDs and sequence numbers within a Conversation, and duplicate logical
`message.created` outbox events. Message authorization, sequence allocation,
matching Outbox insertion, friend/direct/membership/sync transaction assembly, and
post-commit ACK remain application transaction obligations. A unique constraint
alone cannot prove those multi-row operations occurred atomically.

With a disposable PostgreSQL database configured through libpq variables, run
`python3 -m unittest discover -s tests/database -v`. The integration test uses
an isolated temporary schema and exercises forward, uniqueness, and rollback.

# Canonical WSS v1 contract

`envelope.schema.json` is the machine-verifiable wire authority. Every JSON frame has `protocolVersion`, `type`, `requestId`, and `payload`; unknown fields are rejected. A successful `message.ack` has `status: committed`, `messageId`, `seq`, and `createdAt`. The echoed `requestId` identifies the client logical send within its Conversation. `message.created` carries that same request identity for local convergence. Server-generated events use a unique event `requestId` except `message.created`, which carries the originating send request identity.

TLS and WebSocket upgrade produce an unauthenticated connection. Before successful `auth.bind`, only `auth.bind`, `ping`, and `pong` are legal. The access token appears only in `auth.bind.payload`, never in the URL, logs, errors, or fan-out. The server checks signature, expiry, session ID, client type, and session epoch against authoritative session state before binding. A revoked or replaced session emits `session.revoked` and closes the connection; later sends cannot succeed. The `auth.ack` echoes the bind request identity.

For `message.send`, the sender identity comes solely from the bound session. Core authorizes Conversation membership before persistence. `(senderId, conversationId, requestId)` is the server idempotency identity. A repeated send with that identity and identical content returns the original committed `messageId`, `seq`, and `createdAt`; it creates no second Message, sequence, or logical Outbox event. Reuse of the identity with different content is rejected. The same request ID in another Conversation is independent. Sequence numbers increase within each Conversation, while message IDs are globally unique.

`message.ack` with `status: committed` is legal only after the Message, sequence allocation, and matching Outbox event commit atomically in PostgreSQL. A rollback or unknown commit outcome must not yield a successful ACK. A rejected send has no persisted Message or Outbox event. NATS delivery and local `message.created` fan-out can repeat; clients converge by Conversation and request/message identity, and Sync supplies eventual completeness. GROUP send persists one logical Message and one logical Outbox event regardless of member count. WSS v1's send content is `TEXT`; Plugin content requires its separate versioned contract. `message.created` is routed only to locally active, authorized Conversation members; Gateway does not decide business membership.

`contracts/fixtures/websocket/` holds the deterministic shared Go/Java vectors. Run `python contracts/websocket/verify.py` to regenerate and compare them, validate the wire schema, run state assertions, and exercise negative mutations. `python contracts/websocket/verify.py --write` updates generated fixtures intentionally.

# Canonical Sync and Plugin API v1 contracts

`../websocket/sync-v1.schema.json` defines the four Sync v1 wire objects: user request/page and Conversation request/page. `v1.schema.json` defines Plugin API v1 manifests, Event subscriptions, Queries, Actions, UI Host calls, and immutable artifact descriptors. `policy-v1.json` fixes the capability and permission map, Query page limit, renderer preflight and sandbox choices, WASM denials and limit classes, upgrade stages, and purge requirements. These files under `contracts/` are the public machine-verifiable authority. The verifier and golden vectors live beside them; implementations must conform to the contracts.

The user cursor is opaque and advances only with friend, Conversation, membership, or plugin state. Message pages use a per-Conversation sequence. A client materializes data and advances the corresponding cursor or contiguous sequence in one transaction. A failed transaction changes neither. Duplicate and out-of-order Messages upsert by `(conversationId, requestId)`, `messageId`, and `(conversationId, seq)`; a conflicting identity is rejected. `contiguous_seq` advances only across a complete prefix. A locally FAILED item with the same Conversation and request identity becomes SENT, and SENT never regresses to FAILED. Web remains memory-only; Desktop and Mobile render account-scoped local materialized state before background Sync.

Each Plugin API surface requires both its declared capability and current permission. A Query request is limited to 100 items; an allowed Query returns a `query.page` with at most the requested number of host-projected items, a matching request page token, a continuation token when `hasMore` is true, and `sideEffects: 0`. A follow-up request presents the prior continuation token. An unauthorized or invalid Query returns no page. Actions are re-authorized at execution, use `(pluginId, conversationId, requestId)` as the idempotency identity, and leave an audit record for every attempt. The Host bridge is the only route to Core data or actions; no direct Core or database access is granted.

A renderer loads only after package hash, signature, manifest schema, API compatibility, permission, resource size, CSP, and entry-point checks succeed. It executes in a sandbox iframe or isolated WebView and reaches UI Host only through the mediated bridge. The verifier's renderer runtime cases reject direct host-sensitive resource access. A `(pluginId, version)` artifact is immutable: package, backend, and renderer hashes cannot change under that identity. Backend and renderer versions must match. Messages referring to Plugin content must retain the referenced renderer version and fallback TEXT. WSS v1's existing `message.send` remains TEXT-only; this contract does not change it.

WASM denies database, server-file, arbitrary-network, and other-plugin-memory access by default. CPU/time, memory, concurrency, storage, and network limits are enforced; three consecutive timeout, panic, or limit violations trigger AUTO_DISABLED. Plugin artifact lifecycle and Conversation instance lifecycle remain distinct. During upgrade the old version serves until snapshot, migration, backend and renderer health checks, and atomic switch succeed. Any failed stage restores the snapshot and leaves the old version serving. DISABLE preserves data; UNINSTALL defaults to RETAINED; PURGE requires an explicit, elevated, audited, retention-confirmed operation.

Run `python contracts/fixtures/sync-plugin/generate.py` to deliberately regenerate canonical shared vectors, then `python contracts/plugin-api/verify.py` to lint schemas and check outcomes. The verifier is an offline contract oracle, not a Plugin or Sync runtime. Query fixtures observe linked result pages, item counts, and zero side effects. Action fixtures record every authorization/audit result, and upgrade fixtures record each attempted stage while the old version serves.

Backend conformance must replace or validate these observations when those implementations arrive. CREATE TABLE users (
    user_id uuid PRIMARY KEY,
    username text NOT NULL UNIQUE,
    display_name text NOT NULL,
    password_hash text NOT NULL,
    created_at timestamptz NOT NULL DEFAULT now(),
    CHECK (length(username) > 0),
    CHECK (length(password_hash) > 0)
);

-- The slot row is replaced atomically on login: session_id rotates and epoch rises.
CREATE TABLE sessions (
    user_id uuid NOT NULL REFERENCES users(user_id),
    client_type text NOT NULL CHECK (client_type IN ('WEB', 'DESKTOP', 'MOBILE')),
    session_id uuid NOT NULL UNIQUE,
    session_epoch bigint NOT NULL CHECK (session_epoch > 0),
    refresh_token_hash text,
    status text NOT NULL CHECK (status IN ('ACTIVE', 'REVOKED')),
    device_id text NOT NULL,
    expires_at timestamptz NOT NULL,
    updated_at timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (user_id, client_type),
    CHECK (status <> 'ACTIVE' OR refresh_token_hash IS NOT NULL)
);

CREATE TABLE conversations (
    conversation_id uuid PRIMARY KEY,
    kind text NOT NULL CHECK (kind IN ('DIRECT', 'GROUP')),
    direct_user_low_id uuid REFERENCES users(user_id),
    direct_user_high_id uuid REFERENCES users(user_id),
    next_seq bigint NOT NULL DEFAULT 1 CHECK (next_seq > 0),
    created_by uuid NOT NULL REFERENCES users(user_id),
    group_create_request_id uuid,
    created_at timestamptz NOT NULL DEFAULT now(),
    CHECK ((kind = 'DIRECT' AND direct_user_low_id IS NOT NULL AND direct_user_high_id IS NOT NULL
            AND direct_user_low_id < direct_user_high_id AND group_create_request_id IS NULL)
        OR (kind = 'GROUP' AND direct_user_low_id IS NULL AND direct_user_high_id IS NULL
            AND group_create_request_id IS NOT NULL)),
    UNIQUE (conversation_id, direct_user_low_id, direct_user_high_id),
    UNIQUE (direct_user_low_id, direct_user_high_id),
    UNIQUE (created_by, group_create_request_id)
);

CREATE TABLE friendships (
    user_low_id uuid NOT NULL REFERENCES users(user_id),
    user_high_id uuid NOT NULL REFERENCES users(user_id),
    direct_conversation_id uuid NOT NULL UNIQUE,
    created_at timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (user_low_id, user_high_id),
    CHECK (user_low_id < user_high_id),
    FOREIGN KEY (direct_conversation_id, user_low_id, user_high_id)
        REFERENCES conversations(conversation_id, direct_user_low_id, direct_user_high_id)
);

CREATE TABLE conversation_members (

    role text NOT NULL CHECK (role IN ('OWNER', 'MEMBER')),
    joined_at timestamptz NOT NULL DEFAULT now(),

CREATE TABLE plugin_artifacts (
    plugin_id text NOT NULL,
    version text NOT NULL,
    package_hash text NOT NULL,
    backend_hash text NOT NULL,
    renderer_hash text NOT NULL,
    manifest jsonb NOT NULL,
    status text NOT NULL CHECK (status IN ('UPLOADED', 'VALIDATING', 'VERIFIED', 'REJECTED')),
    created_at timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (plugin_id, version),
    CHECK (length(plugin_id) > 0 AND length(version) > 0),
    CHECK (length(package_hash) > 0 AND length(backend_hash) > 0 AND length(renderer_hash) > 0)
);

CREATE FUNCTION reject_plugin_artifact_mutation() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
    IF (OLD.plugin_id, OLD.version, OLD.package_hash, OLD.backend_hash, OLD.renderer_hash, OLD.manifest)
       IS DISTINCT FROM
       (NEW.plugin_id, NEW.version, NEW.package_hash, NEW.backend_hash, NEW.renderer_hash, NEW.manifest) THEN
        RAISE EXCEPTION 'plugin artifact identity and bytes are immutable';
    END IF;
    RETURN NEW;
END $$;
CREATE TRIGGER plugin_artifact_immutable BEFORE UPDATE ON plugin_artifacts
    FOR EACH ROW EXECUTE FUNCTION reject_plugin_artifact_mutation();

CREATE FUNCTION reject_plugin_artifact_delete() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
    RAISE EXCEPTION 'plugin artifact versions cannot be deleted';
END $$;
CREATE TRIGGER plugin_artifact_no_delete BEFORE DELETE ON plugin_artifacts
    FOR EACH ROW EXECUTE FUNCTION reject_plugin_artifact_delete();

CREATE TABLE plugin_instances (
    conversation_id uuid NOT NULL REFERENCES conversations(conversation_id),
    plugin_id text NOT NULL,
    active_version text,
    desired_version text,
    previous_version text,
    status text NOT NULL CHECK (status IN ('INSTALLING', 'ENABLED', 'DISABLED', 'INSTALL_FAILED', 'AUTO_DISABLED', 'UNINSTALLED', 'RETAINED', 'PURGED')),
    grants jsonb NOT NULL DEFAULT '{}'::jsonb,
    updated_at timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (conversation_id, plugin_id),
    FOREIGN KEY (plugin_id, active_version) REFERENCES plugin_artifacts(plugin_id, version),
    FOREIGN KEY (plugin_id, desired_version) REFERENCES plugin_artifacts(plugin_id, version),
    FOREIGN KEY (plugin_id, previous_version) REFERENCES plugin_artifacts(plugin_id, version)
);

CREATE TABLE plugin_kv (
    conversation_id uuid NOT NULL,
    plugin_id text NOT NULL,
    key text NOT NULL,
    value jsonb NOT NULL,
    schema_version integer NOT NULL CHECK (schema_version > 0),
    PRIMARY KEY (conversation_id, plugin_id, key),
    FOREIGN KEY (conversation_id, plugin_id) REFERENCES plugin_instances(conversation_id, plugin_id)
);

CREATE TABLE messages (
    server_message_id uuid PRIMARY KEY,
    conversation_id uuid NOT NULL REFERENCES conversations(conversation_id),
    sender_id uuid NOT NULL REFERENCES users(user_id),
    request_id uuid NOT NULL,
    seq bigint NOT NULL CHECK (seq > 0),
    kind text NOT NULL CHECK (kind IN ('TEXT', 'PLUGIN')),
    text_body text,
    plugin_id text,
    plugin_version text,
    fallback_text text,
    created_at timestamptz NOT NULL DEFAULT now(),
    UNIQUE (conversation_id, request_id),
    UNIQUE (sender_id, conversation_id, request_id),
    UNIQUE (conversation_id, seq),
    UNIQUE (server_message_id, conversation_id),
    FOREIGN KEY (plugin_id, plugin_version) REFERENCES plugin_artifacts(plugin_id, version),
    CHECK ((kind = 'TEXT' AND text_body IS NOT NULL AND plugin_id IS NULL AND plugin_version IS NULL)
        OR (kind = 'PLUGIN' AND plugin_id IS NOT NULL AND plugin_version IS NOT NULL AND fallback_text IS NOT NULL))
);

CREATE TABLE outbox_events (
    event_id uuid PRIMARY KEY,
    aggregate_type text NOT NULL,
    aggregate_id uuid NOT NULL,
    event_type text NOT NULL,
    conversation_id uuid REFERENCES conversations(conversation_id),
    message_id uuid,
    payload jsonb NOT NULL,
    created_at timestamptz NOT NULL DEFAULT now(),
    published_at timestamptz,
    attempts integer NOT NULL DEFAULT 0 CHECK (attempts >= 0),
    FOREIGN KEY (message_id, conversation_id) REFERENCES messages(server_message_id, conversation_id),
    CHECK ((event_type = 'message.created' AND message_id IS NOT NULL AND conversation_id IS NOT NULL)
        OR (event_type <> 'message.created' AND message_id IS NULL))
);
CREATE UNIQUE INDEX outbox_one_message_created ON outbox_events(message_id) WHERE event_type = 'message.created';
CREATE INDEX outbox_unpublished ON outbox_events(created_at, event_id) WHERE published_at IS NULL;
