行为、源码归属、依赖方向、共享支持范围、最小性、
旧 Social 成果迁移和测试有效性。

必要时创建或复用 Social PR 以验证完整任务差异，
但不要在本轮自动合并该业务 PR。

如果 Task Spec 要求额外集成条件，必须满足其实际要求，
不能仅为本轮报告好看而提前标 done。

本轮完成边界：
整改已经通过 PR 集成；
本地 main 安全同步且合并结果验证通过；
Social 达到现行任务规定的独立验收和真实 CI 闭合状态。

本轮不继续执行 Message、E2E、Java、客户端、插件或 S2。
Social 完成不等于 S1 Gate PASS。

十、交付与停止条件
────────────────────

最终报告：

1. 整改 PR 地址、状态、合并方式及实际 merge SHA。
2. PR 审查范围、head/base/tested SHA 与真实 CI 作业结果。
3. 合并后 main CI 和验证结论。
4. 本地 main 所在路径、SHA、origin/main SHA、工作树状态。
5. 原始/整改/Auth/Social 历史工作区哪些被保留，是否存在未解决所有权。
6. 外置验收证据如何转为可共享的稳定引用。
7. Social 旧成果如何复用，Task Spec 的实际路径如何绑定。
8. Social 候选 SHA、Review、hosted CI、任务状态及 PR 状态。
9. 当前唯一 Current Task、S1 Gate 状态和下一条准确动作。
10. 所有真实阻塞、未执行项、skip 和研究记录限制。

真实停止条件包括：
- 无法安全解决的工作区所有权或分叉；
- 仓库权限、必须的人类 Review 或保护规则阻塞；
- 新发现的未批准架构/契约选择；
- 独立 Agent 能力确实不可用；
- 无法取得必要验收证据。

普通测试失败或 Review FAIL 应继续修复，不立即把问题交回用户。
但不得绕过上述真实阻塞。

现在开始核验现场和最终交付，
依序完成整改 PR、合并后验证、本地同步，以及 Social 恢复与执行。
