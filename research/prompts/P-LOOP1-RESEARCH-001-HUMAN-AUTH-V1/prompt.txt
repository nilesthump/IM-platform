\============================================================
3\. Research Recorder 的基本原则
===========================

Recorder 的核心必须是：

脚本 / runner / wrapper / hook。

不是：

让被观察 Agent 在任务结束以后自己回忆并写“我刚才做了什么”。

原则：

Agent 是被观察对象。
Recorder 是观察仪器。

目标比例：

约 80%～90% 事实应由脚本自动获得，例如：

- timestamps
- Git SHA
- branch
- dirty/clean
- diff
- changed paths
- command
- exit code
- duration
- verifier result
- test result
- Review verdict
- CI result
- file hash

只有脚本无法理解的语义事件才允许 Agent 显式报告，例如：

- architecture\_conflict
- external\_blocker
- 简短 decision rationale

不得依赖 Agent 自述来判断：

PASS / FAIL / CI success / test success。

\============================================================
4\. 禁止记录隐藏推理
============

禁止：

- hidden chain-of-thought
- private reasoning trace
- 猜测模型内部推理
- 要求 Agent 暴露内部 CoT

允许：

结构化、简短、公开的 decision summary，例如：

{
"decision": "use existing contract fixture",
"reason": "changing the public contract is outside task scope"
}

这只是公开理由摘要，不是模型隐藏思维链。

\============================================================
5\. Instrumentation Epoch
=========================

Recorder 正式通过独立验收后，必须建立一个明确的：

INSTRUMENTATION\_EPOCH

至少记录：

- timestamp
- recorder schema version
- accepted recorder commit SHA
- recorder task ID
- acceptance evidence
- exact point from which prospective traces are considered complete

定义：

Instrumentation Epoch 之前：
retrospective / pilot / backfill evidence

Instrumentation Epoch 之后：
prospective instrumented data

未来论文中的主要定量结果应优先使用 Epoch 之后的数据。

不得把 Epoch 之前的数据伪装成完整 prospective trace。

\============================================================
6\. 已经完成的历史 Agent
=================

对于已经完成的 Agent / Task，例如 CTRL-001、CTRL-002：

不得伪造：

- model calls
- token usage
- tool calls
- exact prompt
- exact timing
- reasoning
- context size
- cost

除非当时已有真实 durable evidence。

允许从以下来源 backfill：

- Git commits
- Git diff
- Task Spec
- checkpoint
- durable review evidence
- verifier output
- CI evidence（若当时存在）
- progress/current
- repository logs

所有 retrospective 数据必须明确：

{
"collection\_mode": "retrospective\_backfill",
"backfilled": true
}

无法证明的字段：

"unavailable"

禁止猜测。

建议为已有完成任务生成 backfill metadata，
至少覆盖当前已有重要 bootstrap/control-plane tasks。

这些历史数据主要用于：

- pilot study
- workflow evolution
- early failure modes
- mutation benchmark design

不要和未来 prospective dataset 无标记混合统计。

\============================================================
7\. 当前暂停中的 Agent
================

当前 paused Agent 是特殊情况。

它的任务可能已经进行了一部分，
但这一部分没有 Recorder。

恢复后必须建立新的 Run：

capture\_mode = "prospective\_resume"

必须标记：

{
"pre\_recorder\_work": true,
"pre\_recorder\_trace\_complete": false
}

Recorder 激活时应捕获：

- 当前 commit
- 当前 branch
- 当前 dirty state
- 当前 diff
- current task
- task state
- task ownership
- relevant hashes
- checkpoint

暂停前能够从 durable evidence 恢复的内容只能：

backfill = true

暂停前无法观测的信息：

unavailable

从 Recorder 激活以后，
才开始记录真实 prospective trace。

不得假装这个 Task 从第一秒开始都有完整 Recorder。

9\. Prompt 必须纳入记录

未来每个 Agent Run 应尽可能记录 Human 提交给 Agent 的实际 task prompt。

例如：

或者 content-addressed equivalent。

- prompt\_id

- capture mode
- source
- template version（若有）
- task\_id

对于普通、非敏感 Human Prompt：

\============================================================
10\. Secret Handling
====================

绝对禁止记录：

- API key
- password
- token
- `.env`
- credentials
- private signing data
- raw auth headers

Recorder 不得 dump 整个 environment。

Prompt / command / stdout / stderr 记录必须考虑 secret redaction。

如果发现疑似 secret：

- 拒绝直接持久化敏感值；
- 记录 redaction / instrumentation warning；
- 不把 secret 写进研究 artifact。

不得为了“实验完整性”降低安全要求。

- test\_result

\============================================================
13\. 数据完整性
==========

Recorder 应提供基本完整性保护。

至少：

- seq 单调递增；
- run\_id 一致；
- schema validation；
- finished run 默认不得通过普通命令修改历史 raw events；
- 对 malformed JSON / partial write / interrupted run 有检测；
- 能检测 duplicate sequence。

如实现成本合理，可加入：

- event hash
- previous event hash
- final manifest hash

形成简单 hash chain。

不要为了 cryptographic sophistication 过度设计。

Git 历史 + deterministic validation + hashes 已经是主要证据。

\============================================================
16\. Command Recorder
=====================

实现最小命令 wrapper。

例如：

tools/research/run-command

或平台适合的等价入口。

它必须：

1. 接收真实 command；
2. 写 command\_started；
3. 记录 start timestamp；
4. 真正执行命令；
5. 获取真实 exit code；
6. 获取 duration；
7. 必要时安全保存 stdout/stderr 或其 hash；
8. 写 command\_finished；
9. 原样传播 command exit code。

关键原则：

如果真实 command exit 1：

Recorder 不得把它变成 PASS。

例如未来：

research-run-command pytest ...

必须由脚本真正执行 pytest。

禁止：

Agent 说“pytest 通过”
→ Recorder 就写 PASS。

\============================================================
24\. 已暂停 Agent 的恢复协议
====================

Recorder 完成后，需要为原 paused Agent 留下一段明确 resume instruction。

恢复时它必须：

1. 继续原来的 Task，而不是重新选 Task；
2. 保留之前 ownership；
3. 不重写暂停前历史；
4. 初始化一个新的 research run；
5. capture\_mode = prospective\_resume；
6. 标记 pre\_recorder\_work = true；
7. 捕获恢复时 Git / Task / diff 状态；
8. 从恢复后的第一条可观察操作开始记录；
9. 暂停前的信息仅能 backfill；
10. 不得伪造之前 token / model call / tool trace。

最终 Handoff 必须告诉 Human：

原 Agent 是否可以安全恢复；
从哪个 commit/worktree/task 继续；
Recorder 从哪个时间点开始有真实 trace。

F.
finish-run：

- final state 捕获
- duration 可得
- diff 可得

G.
interrupted/partial run：

- 可检测
- 不把 partial run 当 complete

H.

- 不冒充真实 Human Decision

I.
Backfill：

- backfilled=true
- unavailable 字段不会被猜测

J.
Prospective Resume：

- pre\_recorder\_work=true
- trace completeness 正确标记

K.
Secret safety：

- 不 dump environment
- secret-like input 不应明文进入 durable research log

L.
Repository safety：

- existing governance verifier 仍然通过
- 不存在任何 IM 产品实现变更
- 原 paused Task 没有被标记完成
- 原 ownership 未被错误转移

不要写论文。

不要做营销文档。

不要做 dashboard。

\============================================================
28\. Acceptance / Review
========================

实现完成后：

先运行本 Task 所需本地 verification。

但：

Local PASS ≠ accepted.

必须遵循仓库现有 independent review 规则。

如果可以真实委派 fresh independent Review Agent：

执行独立 review。

如果 reviewer FAIL：

进入正常 fix → fresh review 循环。

如果当前环境无法提供真正独立 reviewer：

停在 review / handoff。

不得伪造 PASS。

不得让本 Recorder Implementation Agent 自己接受自己的工作。

\============================================================
29\. 最终 Handoff 给 Human
=======================

最终只需要给 Human 一个清晰摘要：

1. Recorder 是否完成；
2. Instrumentation Epoch 是否已经建立；
3. accepted commit SHA；
4. Recorder schema version；
5. 新增/修改了哪些控制面文件；
6. 未来如何：
   - register prompt
   - start run
   - run command
   - record human decision
   - finish run
7. 历史 completed tasks 如何 backfill；
8. 当前 paused Agent 如何 resume；
9. 哪些字段当前 harness 无法观察；
10. test / review / acceptance 结果；
11. 是否存在 architecture/governance blocker；
12. Human 是否还需要做任何决策。

然后停止。

DO NOT CONTINUE PRODUCT IMPLEMENTATION.
