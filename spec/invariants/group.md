# Group 不变量

从属于canonical §4.3/§5/§6.7与ADR-0013；公共机器契约唯一contracts/，不得从实现反推。

| Rule ID | 无论实现如何都成立 |
| --- | --- |
| GROUP-I-001 | 非有效Session、非GROUP、非成员加人、目标非操作者好友的调用不得产生群、成员、幂等成功结果、Sync或Outbox新效果。 |
| GROUP-I-002 | A-B好友、B-C好友而A-C非好友时，B作为有效群成员添加C必须成功；不能以创建者好友或OWNER限制拒绝。 |
| GROUP-I-003 | 相同幂等key及规范内容并发/串行只产生一次逻辑操作，重放同原结果；异内容拒绝且不改变已提交结果。不同操作者/request重叠添加成员也不重复成员或变更事件。 |
| GROUP-I-004 | 群创建含创建者；每群每用户最多一个有效成员。任一目标/写入失败整体回滚，不存在部分群、部分成员、孤立成功收据或仅事件无数据。 |
| GROUP-I-005 | 只有群、成员、操作结果、所有必要低频事件及Outbox都持久提交后才成功。响应丢失后重试不得建第二群/重复加人；未知commit不能伪装已回滚。 |
| GROUP-I-006 | 群元数据经User Sync，不使用消息seq推进用户cursor；消息仍单message/单logicalOutbox、conversation seq及durable ACK。客户端数据/cursor原子提交、重复乱序收敛、不跨gap。 |
| GROUP-I-007 | 只有当前有效成员获取群快照/消息；新增成员能获得同一会话，全部有效成员各端在线或重连最终补齐；不向外部用户错投/泄露群成员。 |
| GROUP-I-008 | UI以稳定senderId关联真实成员展示信息，不以翻译、显示名或好友DIRECT推定发言者；Web无聊天持久化/离线历史，Desktop/Mobile保持账号隔离。 |
| GROUP-I-009 | 真实拒绝/失败/未确认可分辨；未知错误/内部错误/不变量破坏不得吞掉、回假空数据或成功。 |
